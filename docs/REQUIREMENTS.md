# OpenType — 议题要求与提交 Checklist

## 项目目标

开发一个语音输入法产品，帮助用户提高文本输入效率。要求较好地平衡**准确度、易用性、响应速度、成本**等关键因素。

---

## 评审规则

| 维度 | 权重 | 关注点 |
|------|------|--------|
| **作品完整度与创新性** | 40% | 产品设计合理性、功能完整度、交互流畅度、是否新颖有创意 |
| **开发过程与质量** | 40% | 架构清晰度、代码健壮度（逻辑/规范/可读性）、PR 数量与质量、commit 分布 |
| **演示与表达** | 20% | demo 视频清晰完整度，是否完整表达功能和效果 |

---

## 开发节奏要求

- **全周期持续交付**：禁止最后一天一次性导入所有代码（直接无效）
- **commit 分布**：时间戳必须落在批次开始与截止时间之内
- **主分支可运行**：每次 PR 合并后，main 分支需保持可运行状态

---

## PR 规范 Checklist

每个 PR 必须满足：

- [ ] **只做一件事**：单一功能，大功能拆分为多个 PR
- [ ] **标题清晰**：一句话说明做了什么
- [ ] **描述完整**：包含以下四项：
  - [ ] 功能描述（作用与使用方式）
  - [ ] 实现思路（技术选型 / 核心逻辑）
  - [ ] 测试方式（如何验证功能正常）
  - [ ] 依赖说明（如有第三方库，列明并说明原创部分）
- [ ] **复用声明**：如复用过去代码，在 PR 描述中注明来源

---

## 最终提交 Checklist

### 代码仓库

- [ ] 公开的 GitHub 仓库，已正确设置远程地址
- [ ] README 包含：项目说明、功能列表、技术栈、使用方法
- [ ] README 声明所有第三方依赖（本项目为纯 Swift，无第三方依赖）
- [ ] commit 历史连续分布，非一次性提交

### Demo 视频

- [ ] 上传至可访问平台（bilibili / 云盘等）
- [ ] 用声音完整讲解，覆盖核心功能模块
- [ ] 链接放在 README **显眼位置**（不藏在子文件夹）

### README 文档

- [ ] 项目功能说明
- [ ] 技术架构概述
- [ ] 运行方式
- [ ] Demo 视频链接（显眼位置）
- [ ] 第三方依赖声明
- [ ] 原创功能说明
